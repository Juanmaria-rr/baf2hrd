Procesamiento

  1. Parsear AD → Ref_Reads, Alt_Reads. DP de respaldo = Ref + Alt si DP es NaN.
  2. Normalizar ALT: <*> → N; multi-alélicos: conservar sólo el primer alelo.
  3. Calcular BAF:
BAF = Alt_Reads / (Ref_Reads + Alt_Reads) [0 si denominador = 0]
  1. Inferir genotipo: BAF < 0.01 → 0/0 | BAF > 0.99 → 1/1 | resto → 0/1.
  2. QC strand-bias: una posición es flagged si Alt_Reads > 0 AND (alt_fwd == 0 OR alt_rev == 0). Razón: artefactos de PCR clásicos aparecen solo en una hebra.

STAGE 1

Per-sample BAF analysis

baf_to_hrd_pipeline.py → run_script1()

1.1 · Carga y normalización de segmentos

  • Fichero esperado: {sample}_100kb_abs_segtable_free_purity_filtered_unique.csv
  • Columnas canónicas: chromosome, start, end, total_cn. Si hay nMajor, nMinor, se calcula total_cn = nMajor + nMinor (con advertencia si difiere >0.5 del valor existente).
  • Normalización cromosómica: strip del prefijo chr; X→23, Y→24; drop de rows con chr no numérico.
  • HRD suffix lookup: muestras que terminan en -HRD (ej. JBLAB17012-HRD) buscan segmentos con el nombre base (JBLAB17012). Esto es correcto: comparten la misma biología de CN pero el BAF se mide con el panel HRD.

1.2 · Filtros aplicados a las posiciones BAF

FiltroCriterioVariable
DP mínimoDP ≥ dp para cada valor en DP_VALUESDP_VALUES = [0, 2, 4, 8]
Strand-biasproblematic_reason IS NULL (columna _ok)Calculado en Stage 0b
DP > 0Aplicado adicionalmente en prepare_baf_origin()Hardcoded
Posiciones NaNDrop filas con NaN en CHROM, POS o BAF_n—
Los 4 valores de DP se procesan en paralelo por muestra (bucle interno). Cada valor genera un conjunto de estadísticas separado, lo que permite comparar el efecto del filtrado.

1.3 · Corrección por pureza (opcional)

Se aplica solo si se proporciona un purity_file con columnas sample, purity, ploidy.

BAF_corrected = 0.5 + (BAF_raw - 0.5) / purity [si BAF ≥ 0.5] BAF_corrected = 0.5 - (0.5 - BAF_raw) / purity [si BAF < 0.5] BAF_corrected = clip(BAF_corrected, 0, 1)
⚠️ En las muestras TSO500 actuales purity_file = null, por lo que no se aplica corrección por pureza. BAF_corrected = BAF_raw. Los thresholds de calibración también usan outer_mass_raw (sin corrección) para mantener la misma escala. Si en algún momento se activa la corrección, los thresholds deberían recalibrarse.

1.4 · Binning BAF y cálculo de outer/inner mass

Para cada segmento se dividen las posiciones BAF en N_BINS = 20 bins uniformes en [0, 1] (ancho = 0.05):

bins: [0.00–0.05), [0.05–0.10), ..., [0.95–1.00] (el último bin es cerrado por la derecha)

Para cada bin se calcula count (n posiciones) y ratio = count / n_total_del_segmento (tanto para BAF corrected como raw).

outer_mass (= outer_mass_raw)

Suma de ratio de los bins donde:
upper ≤ 0.25 OR lower ≥ 0.75

Bins outer: [0.00–0.05), [0.05–0.10), ..., [0.20–0.25), [0.75–0.80), ..., [0.95–1.00]

Interpreta: fracción de posiciones con BAF extremo (cerca de 0 o 1). Alta en LoH.

inner_mass

Suma de ratio de los bins donde:
0.25 ≤ lower < 0.75 AND upper ≤ 0.75

Bins inner: [0.25–0.30), ..., [0.70–0.75)

Interpreta: fracción de posiciones en zona central. Alta en segmentos balanceados.
⚠️ La variable de decisión en Stage 3 es outer_mass_raw (calculada desde el BAF sin corrección de pureza), no outer_mass (desde BAF corregido). Esto asegura consistencia con la calibración. Si el campo outer_mass_raw no existe en el CSV, el código busca outer_mass_raw_x, outer_mass_raw_y (artefactos de merge pandas) y finalmente cae a outer_mass con advertencia.

CALIBRACIÓN

Calibración de thresholds outer_mass

calibrate_thresholds.py

Objetivo y datos de entrada

  • Input: el CSV merged (Stage 2) de las muestras ASCAT-downsampled, que contienen nMajor / nMinor como ground-truth.
  • Feature: outer_mass_raw (fracción BAF sin corrección de pureza).
  • Filtro de muestra opcional: calibration_samples_file (lista de IDs) para un split 80/20 train/val honesto usando split_samples.py.
  • Mínimo segmentos por estado alélico: min_samples = 50.

Proceso por filtro DP

Para cada valor de dp_filter ∈ [0, 2, 4, 8]:

  1. Filtrar el CSV a filas con dp_filter = dp y nMajor/nMinor not null.
  2. Clasificar cada segmento por estado alélico: LoH (nMin=0 o nMaj=0), Balanced (nMaj=nMin), AI (resto).
  3. Para cada total_cn con suficientes datos, construir comparaciones binarias en orden de prioridad:
    • LoH vs Balanced
    • LoH vs AI
    • AI vs Balanced
  4. Para cada comparación: calcular ROC y seleccionar threshold por índice de Youden (argmax TPR−FPR).

Métricas de separabilidad reportadas

MétricaDescripciónUmbral orientativo
AUC-ROCÁrea bajo la curva ROC>0.80 = buena separación
Cohen's dTamaño del efecto>0.80 = LARGE, >0.50 = MEDIUM, ≤0.50 = LOW
Sensitivity / SpecificityEn el threshold de Youden—
Mann-Whitney pSignificación de diferencia entre distribuciones—

Formato del JSON de salida

{ "0": { // dp_filter "2": { // total_cn "loh_vs_balanced": 0.9312, "loh_vs_ai": 0.9127, "ai_vs_balanced": 0.8543 }, "3": { ... }, ... }, "2": { ... }, "4": { ... }, "8": { ... } }
El código soporta también el formato plano (sin clave de DP), aplicando los mismos thresholds a todos los DP. Si se usa el formato plano, Stage 3 emite una advertencia.

Sobre el check de n_positions ≥ 5

No hay descarte de segmentos por número de posiciones BAF. El check n_positions >= 5 existe únicamente en functions.py dentro de calculate_enhanced_features_per_segment(), y sólo condiciona el cálculo de features estadísticas (skewness, kurtosis, bimodalidad): con <5 posiciones esas features se ponen a 0. No hay ninguna regla que descarte el segmento de la clasificación CN.

Post-merge de segmentos adyacentes

  • Función: merge_adjacent_segments_by_allelic_state()
  • Criterio: dos segmentos se fusionan si están en el mismo cromosoma, tienen el mismo A_cn y B_cn, y la distancia entre ellos es ≤ MAX_GAP_BP_FOR_MERGE = 1 bp.
  • En el segmento fusionado: confidence = min, tier = worst_tier (tier1 < tier2 < tier3 < tier3_heuristic < tier3_ai_default < no_baf).
  • Se generan dos ficheros por muestra×DP: _premerge_scarHRD_input.txt y _postmerge_scarHRD_input.txt.

STAGE 4

scarHRD scoring

run_scarHRD.R

Parámetros de llamada

  • Función R: scarHRD::scar_score()
  • Referencia genómica: grch37
  • Modo: seqz = FALSE (input de copy-number directo, no Sequenza)
  • Directorio de trabajo: subdirectorio temporal por muestra (limpiado tras cada run)

Outputs

  • ALL_scarHRD_scores.csv: una fila por muestra con las métricas HRD.
  • Métricas típicas de scarHRD: HRD (score total), LST (large-scale transitions), LOH (LoH score), TAI (telomeric allelic imbalance).
  • failed_samples.txt: muestras que fallaron.
Se procesan todos los ficheros *scarHRD_input*.txt del directorio de input, incluyendo todos los DP y estados pre/post-merge. El SampleID codifica dp y merge_state, lo que permite distinguirlos en el CSV final.

REVISIÓN

Puntos críticos y posibles fuentes de error

Motivados por la baja correlación HRD calculado vs gold-standard

1. LoH ausente para CN=6 y CN=8

Para CN=6, las únicas opciones son AI (4:2) o Balanced (3:3). Para CN=8 son AI (6:2) o Balanced (4:4). Si una muestra tiene CN=6 LoH (6:0) — posible en tumores muy amplificados con pérdida de un alelo — se clasificará erróneamente como AI o Balanced. Idem para CN=8 LoH (8:0).

La lógica en el código para CN=6 también parece invertida respecto a la intuición biológica: outer_mass > threshold → 4:2 (AI), cuando mayor outer_mass debería indicar mayor imbalance (normalmente LoH). Esto puede deberse a la distribución empírica de los datos de calibración para CN=6, pero merece verificación.

2. CN=3 no considera Balanced (1.5:1.5 no entero)

Para CN=3, solo se considera LoH (3:0) o AI (2:1). Un segmento de CN=3 que en realidad es AI con composición ambigua siempre irá a 2:1, lo cual puede ser correcto estadísticamente, pero el threshold está calibrado como loh_vs_ai sin posibilidad de balanced.

3. Ploidy calculada como media(totalCN)

ploidy = mean(totalCN) no ponderado por la longitud de los segmentos. Un segmento de 100 Mb con CN=4 y diez segmentos de 1 Mb con CN=2 darán una ploidy ≈ 2.18, cuando la ploidy real debería ser ~3.8. Esta estimación incorrecta de ploidy se pasa a scarHRD y puede afectar los scores.

4. Default "no BAF" siempre es Balanced o AI (nunca LoH)

Cuando un segmento no tiene ninguna posición BAF (outer_mass_raw = NaN), el default es siempre el estado no-LoH: CN=2 → 1:1, CN=3 → 2:1, CN=4 → 2:2, etc. Esto introduce un sesgo anti-LoH en muestras con baja cobertura o segmentos sin SNPs en el panel. Segmentos en cromosomas con poco contenido heterocigoto (ej. regiones pericéntricas) serán sistemáticamente clasificados como balanceados.

5. Sin corrección de pureza en TSO500

Los thresholds se calibraron en muestras ASCAT-downsampled también sin corrección de pureza (por consistencia), pero la pureza real afecta la distribución del BAF y por tanto del outer_mass. Muestras con baja pureza tumoral tendrán outer_mass desplazado hacia el centro (más balanceado), lo que puede hacer que LoH reales sean clasificados como AI o Balanced.
Acción sugerida: verificar si hay estimaciones de pureza disponibles de los análisis DRAGEN/TSO500.

6. Thresholds fijos para CN≥7 (heurísticos)

Para CN=7 y CN>8 no hay calibración: se usa un threshold fijo de 0.95. Si estos valores de CN son frecuentes en las muestras analizadas, contribuirán ruido al HRD score. Adicionalmente, para CN>8 even el estado AI asignado es (cn/2+1):(cn/2-1), que puede no ser el más frecuente biológicamente.

7. Posible drift entre datos de calibración y aplicación

Los thresholds se calibraron con el run 20260406 (ASCAT-downsampled). Si las muestras TSO500 actuales tienen una distribución de outer_mass diferente (por batch effects de sequencing, panel distinto entre HRD y no-HRD, etc.), los thresholds fijos pueden no ser óptimos.
Check sugerido: comparar histogramas de outer_mass por CN entre el set de calibración y las muestras TSO500.

8. scarHRD recibe segmentos pre- y post-merge en el mismo run
